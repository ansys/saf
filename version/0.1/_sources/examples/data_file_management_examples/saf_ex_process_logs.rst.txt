.. _saf-ex-process-logs:

Process logs
############

.. _saf-ex-process-logs-summary:

.. topic:: Objective

  Display the outputs of a process in a log file in the solution UI.

  Source code for this example is in the `solution-examples <https://github.com/ansys/solution-examples>`_ repository.



.. _saf-ex-process-logs-objective:

:material-outlined:`ads_click;1.25em;sd-text-primary` Objective
==================================================================

From a backend perspective, a solution app is about triggering and orchestrating simulation processes (``pre``, ``solve`` and ``post``). End users may want to access the log files generated by a process and to display those in the UI. This example shows how to read a log file and display its content in the solution UI.

.. _saf-ex-process-logs-prerequisites:

:material-outlined:`task;1.25em;sd-text-primary` Prerequisites
=========================================================================

To display the content of a log file in the solution UI, you need the ``html.Pre`` component from the **Dash HTML Components** library. For more information, see the Plotly Dash `html.Pre <https://dash.plotly.com/dash-html-components/pre>`_ documentation.

.. vale on

.. _saf-ex-process-logs-solution:

:octicon:`code-square;1em;sd-text-primary` Solution
======================================================

To display logs while a process is running, work through the following sequence of tabs.

.. tab-set::

  .. tab-item:: 1️⃣Backend
    :name: saf-ex-process-logs-backend-tab

    Create the solution definition.


    .. dropdown:: Define the step model
      :name: saf-ex-process-logs-backend-drop-1
      :open:

      For the purposes of this example, create a file and write the current time in it.

      Create a ``StepModel`` class named ``ProcessLogsStep`` with a transaction method to generate a log file and that has the following two fields:

      * ``wait_time``: a float value that represents the time to wait
      * ``log_file``: a ``FileReference`` field to store the log file

      In the following code snippet, note the highlighted lines:

      * ``@long_running``: This is a decorator that specifies that the method is asynchronous. This is important because you want to continuously display the content of the log file in the UI while the process is running.
      * ``self.transaction.upload(["log_file"])``: This uploads the log file from the method directory to the project directory while the process is running.

      .. code-block:: python
        :emphasize-lines: 11, 21
        :caption: solution/process_logs_step.py

        import time
        from ansys.saf.glow.solution import StepModel, StepSpec, transaction, FileReference, long_running


        class ProcessLogsStep(StepModel):
            """Process Logs step model."""

            wait_time: float = 10
            log_file: FileReference = FileReference("my_process_logs.txt")

            @transaction(self=StepSpec(upload=["log_file"], download=["wait_time"]))
            @long_running
            def my_process(self) -> None:
                """Wait for some time."""
                start_time = time.time()
                while (time.time() - start_time) < self.wait_time:
                    file = open(self.log_file.path, "a")
                    current_time = time.strftime("%Y-%m-%d %H:%M:%S", time.localtime())
                    file.write(current_time + "\n")
                    file.close()
                    self.transaction.upload(["log_file"])
                    time.sleep(1)



  .. tab-item:: 2️⃣Frontend
    :name: saf-ex-process-logs-frontend-tab

    Create a simple button to trigger the ``my_process`` transaction, read the log file, and display the content in the UI.


    .. dropdown:: Create the page layout with the process logs
      :name: saf-ex-process-logs-frontend-drop-1
      :open:

      To implement the static part of the UI, create the page layout with:

      * a button to trigger the ``my_process`` transaction method
      * an ``html.Div`` to display the content of the ``JSON`` file

      **Add page layout and the button**

      .. code-block:: python
        :caption: ui/pages/process_logs_page.py

        from ansys.saf.glow.client import DashClient, callback
        from ansys.saf.glow.solution import MethodStatus
        from dash_extensions.enrich import Input, Output, State, dcc, html, ctx
        from dash_iconify import DashIconify
        import dash_mantine_components as dmc
        from dash.exceptions import PreventUpdate


        from ansys.solutions.examples.solution.definition import ExamplesSolution
        from ansys.solutions.examples.solution.process_logs_step import ProcessLogsStep


        def layout(step: ProcessLogsStep):
            """Layout of the process logs page."""
            return html.Div(
                [
                    html.H1("Process Logs", className="display-3", style={"font-size": "48px", "fontWeight": "bold"}),
                    html.P(
                        "This page demonstrates the usage of process logs in Dash.",
                        className="lead",
                        style={"font-size": "20px"},
                    ),
                    html.Hr(className="my-2"),
                    html.Br(),
                    dmc.Button(
                        "Start",
                        id="start_button",
                        variant="filled",
                        radius="xl",
                        style={"color": "#FFFFFF", "width": "20%"},
                        leftIcon=DashIconify(icon="streamline:startup-solid"),
                    ),
                    html.Div(
                        id="log_container",
                        children=get_logs(step),
                        style={
                            "height": "600px",
                            "width": "100%",
                            "overflowY": "scroll",
                            "border": "1px solid #d9d9d9",
                            "borderRadius": "4px",
                            "padding": "8px",
                            "marginTop": "10px",
                        },
                    ),
                    dcc.Interval(
                        id="interval",
                        interval=1000,
                        n_intervals=0,
                        disabled=not process_in_progress(step),
                    ),
                ]
            )

      **Display the log file**

      The ``html.Div`` component with the ID ``log_container`` displays the content of the log file. The ``get_logs`` method is responsible for reading the log file and returning its content.

      .. code-block:: python
          :caption: ui/pages/process_logs_page.py

          def get_logs(step: ProcessLogsStep) -> html.Div:
              """Return the children containing the lsdyna logs."""
              if step.log_file.exists():
                  try:
                      content = step.log_file.read_text()
                  except Exception as e:
                      return
                  return html.Div(
                      [
                          html.P(
                              "Process logs:",
                              className="lead",
                              style={"font-size": "20px"},
                          ),
                          html.Pre(
                              content,
                              style={"whiteSpace": "pre-wrap", "wordBreak": "break-all", "fontSize": "10px"},
                          ),
                      ]
                  )
              return html.Div("No logs available yet.")

      **Define the callback interval**

      The ``dcc.Interval`` component plays a crucial role in this implementation. When activated, it triggers the callback function to update the content of the log file.

      To control the activation/deactivation of the interval, create a helper function called ``process_in_progress``. (Note that the interval component is only needed when the process is running.)

      Within the ``layout`` function's ``dcc.Interval`` component, the ``disabled`` property invokes the ``process_in_progress`` function.

      Once the transaction completes, the interval is disabled. It is a good practice to disable the interval when it is not needed to avoid unnecessary calls to the backend.

      .. code-block:: python

          def process_in_progress(step: ProcessLogsStep) -> bool:
              """Return True if the process is in progress."""
              return True if step.get_long_running_method_state("my_process").status == MethodStatus.Running else False


    .. dropdown:: Connect the button to the transaction method
      :name: saf-ex-process-logs-frontend-drop-4
      :open:

      **Start the transaction and interval component**

      To implement the interactive part of the UI, create a callback function to call the ``my_process`` transaction method and activate the interval component whenever the :guilabel:`Start` button is clicked.

      .. code-block:: python
        :caption: ui/pages/process_logs_page.py

        @callback(
            Output("interval", "disabled"),
            Input("start_button", "n_clicks"),
            State("url", "pathname"),
            prevent_initial_call=True,
        )
        def start_transaction(n_clicks, pathname):
            """Start the transaction."""
            if ctx.triggered_id == "start_button" and n_clicks:
                project = DashClient[ExamplesSolution].get_project(pathname)
                step = project.steps.process_logs_step
                step.my_process()
                return False
            raise PreventUpdate

      **Update the log file**

      Create a second callback function to update the content of the log file while the process is running.

      .. code-block:: python
        :caption: <ui/pages/process_logs_page.py>

        @callback(
            Output("log_container", "children"),
            Output("interval", "disabled"),
            Input("interval", "n_intervals"),
            State("url", "pathname"),
            prevent_initial_call=True,
        )
        def update_logs(n_intervals, pathname):
            if ctx.triggered_id == "interval" and n_intervals:
                project = DashClient[ExamplesSolution].get_project(pathname)
                step = project.steps.process_logs_step
                if process_in_progress(step):
                    disable_monitoring = False
                else:
                    disable_monitoring = True
                return get_logs(step), disable_monitoring
            raise PreventUpdate
